**3. `apps/backend/src/auth/strategies/local.strategy.ts`**

Extends `PassportStrategy(Strategy)` from `passport-local`. Constructor sets `usernameField: 'email'`. The `validate(email: string, password: string)` method calls `AuthService.validateUser(email, password)` which returns a user object or throws `InvalidCredentialsError`.

```typescript
import { Injectable } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { Strategy } from 'passport-local';

import { AuthService } from '@/auth/auth.service';

@Injectable()
export class LocalStrategy extends PassportStrategy(Strategy) {
  constructor(private readonly authService: AuthService) {
    super({ usernameField: 'email' });
  }

  async validate(email: string, password: string): Promise<{ id: string; email: string; role: string }> {
    return this.authService.validateUser(email, password);
  }
}
```

**4. `apps/backend/src/auth/strategies/jwt.strategy.ts`**

Extends `PassportStrategy(Strategy)` from `passport-jwt`. Extracts token from `Authorization: Bearer <token>` header. Uses `JWT_ACCESS_SECRET` from `process.env`. The `validate` method returns `{ sub: payload.sub, email: payload.email, role: payload.role }`.

```typescript
import { Injectable } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';

export interface JwtPayload {
  sub: string;
  email: string;
  role: string;
  iat?: number;
  exp?: number;
}

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    const secret = process.env['JWT_ACCESS_SECRET'];
    if (!secret) throw new Error('JWT_ACCESS_SECRET environment variable is not set');
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: secret,
    });
  }

  validate(payload: JwtPayload): JwtPayload {
    return { sub: payload.sub, email: payload.email, role: payload.role };
  }
}
```

**7. `apps/backend/src/auth/auth.service.ts`**

Injectable service with these dependencies injected:
- `PrismaService` (for user queries)
- `JwtService` (from `@nestjs/jwt`)
- `RedisService` (for token blacklist)

Methods:

`async signup(dto: SignupDto): Promise<{ accessToken: string; refreshToken: string; user: {...} }>`
- Check if user with email exists: `prisma.user.findUnique({ where: { email: dto.email, deleted_at: null } })`
- If exists, throw `new UserAlreadyExistsError(dto.email)`
- Hash password: `await bcrypt.hash(dto.password, 10)` (async, never sync — per Pitfall 5)
- Create user: `prisma.user.create({ data: { email: dto.email, password: hashedPassword, name: dto.name } })`
- Sign access token with payload `{ sub: user.id, email: user.email, role: user.role }` using `JWT_ACCESS_SECRET` and expiry `JWT_ACCESS_EXPIRES_IN` (15m)
- Sign refresh token with same payload using `JWT_REFRESH_SECRET` and expiry `JWT_REFRESH_EXPIRES_IN` (30d)
- Return `{ accessToken, refreshToken, user: { id: user.id, email: user.email, name: user.name, role: user.role, timezone: user.timezone } }`

`async validateUser(email: string, password: string): Promise<{ id: string; email: string; role: string }>`
- Find user by email (exclude soft-deleted): `prisma.user.findUnique({ where: { email, deleted_at: null } })`
- If not found, throw `new InvalidCredentialsError()`
- Compare password: `await bcrypt.compare(password, user.password)`
- If mismatch, throw `new InvalidCredentialsError()`
- Return `{ id: user.id, email: user.email, role: user.role }`

`async login(userId: string): Promise<{ accessToken: string; refreshToken: string; user: {...} }>`
- Find user by id: `prisma.user.findUnique({ where: { id: userId } })`
- Sign access and refresh tokens (same as signup)
- Return `{ accessToken, refreshToken, user: { id, email, name, role, timezone } }`

`async refresh(oldRefreshToken: string): Promise<{ accessToken: string; refreshToken: string; user: {...} }>`
- Verify the old refresh token: `this.jwtService.verify(oldRefreshToken, { secret: process.env['JWT_REFRESH_SECRET'] })`. Catch verify errors and throw `new InvalidCredentialsError('Invalid or expired refresh token.')`
- Check Redis blacklist: `await this.redisService.get('blacklist:' + oldRefreshToken)`. If present, throw `new InvalidCredentialsError('Token has been revoked.')`
- Find user by `payload.sub` to get current data
- Sign new access + refresh tokens
- Blacklist the OLD refresh token: `await this.redisService.set('blacklist:' + oldRefreshToken, '1', remainingTtl)` where `remainingTtl = payload.exp - Math.floor(Date.now() / 1000)`. If remaining TTL <= 0, use 1 second.
- Return `{ accessToken, refreshToken: newRefreshToken, user: { id, email, name, role, timezone } }`

`async logout(refreshToken: string): Promise<void>`
- Verify the refresh token to get expiry (catch errors silently — logout should succeed even with an invalid token, just clear the cookie)
- If valid, blacklist: `await this.redisService.set('blacklist:' + refreshToken, '1', remainingTtl)`

Private helpers:
- `private signAccessToken(payload: { sub: string; email: string; role: string }): string` — uses `this.jwtService.sign(payload, { secret: process.env['JWT_ACCESS_SECRET'], expiresIn: process.env['JWT_ACCESS_EXPIRES_IN'] ?? '15m' })`
- `private signRefreshToken(payload: { sub: string; email: string; role: string }): string` — uses `this.jwtService.sign(payload, { secret: process.env['JWT_REFRESH_SECRET'], expiresIn: process.env['JWT_REFRESH_EXPIRES_IN'] ?? '30d' })`

- Returns `{ data: { accessToken, user }, meta: {}, errors: [] }`

`@UseGuards(LocalAuthGuard)` + `@Post('login')` — uses Passport local strategy
- `@Req() req: Request` (user attached by Passport as `req.user`)
- `@Res({ passthrough: true }) res: Response`
- Calls `authService.login(req.user.id)`
- Sets refresh token cookie (same as signup)
- Apply `@Throttle()` from `@nestjs/throttler` — limit to 5 requests per 60 seconds on this endpoint
- Returns `{ data: { accessToken, user }, meta: {}, errors: [] }`

`@Post('refresh')` — public endpoint (reads cookie, not bearer token)
- `@Req() req: Request` — reads `req.cookies['refresh_token']`
- `@Res({ passthrough: true }) res: Response`
- If no cookie present, return 401 with `{ data: null, meta: {}, errors: [{ status: 401, title: 'Unauthorized', detail: 'No refresh token provided.' }] }`
- Calls `authService.refresh(oldRefreshToken)`
- Sets NEW refresh token cookie (same options)
- Returns `{ data: { accessToken, user }, meta: {}, errors: [] }`

`@UseGuards(JwtAuthGuard)` + `@Delete('logout')` — requires Bearer token
- `@Req() req: Request` — reads `req.cookies['refresh_token']`
- `@Res({ passthrough: true }) res: Response`
- Calls `authService.logout(refreshToken)` (if present)
- Clears cookie: `res.clearCookie('refresh_token', { httpOnly: true, secure: process.env['NODE_ENV'] === 'production', sameSite: 'strict', path: '/auth' })`
- Returns `{ data: null, meta: { message: 'Logged out successfully.' }, errors: [] }`

**IMPORTANT:** For `@Res({ passthrough: true })`, the type annotation for `res` should use Express `Response` from `express`. Import as `import { Request, Response } from 'express';`. For `@Req()`, the `req.user` type comes from Passport — use a type assertion: `const user = req.user as { id: string; email: string; role: string }`.

**9. `apps/backend/src/auth/auth.module.ts`**

```typescript
import { Module } from '@nestjs/common';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { ThrottlerGuard, ThrottlerModule } from '@nestjs/throttler';
import { APP_GUARD } from '@nestjs/core';

import { AuthController } from '@/auth/auth.controller';
import { AuthService } from '@/auth/auth.service';
import { JwtStrategy } from '@/auth/strategies/jwt.strategy';
import { LocalStrategy } from '@/auth/strategies/local.strategy';

@Module({
  imports: [
    PassportModule,
    JwtModule.register({}),  // Secrets passed per-call in service methods
    ThrottlerModule.forRoot([{ ttl: 60000, limit: 10 }]),  // 10 req/min global default
  ],
  controllers: [AuthController],
  providers: [
    AuthService,
    LocalStrategy,
    JwtStrategy,
    { provide: APP_GUARD, useClass: ThrottlerGuard },
  ],
  exports: [AuthService],
})
export class AuthModule {}
```

Note: ThrottlerGuard is registered as APP_GUARD to apply globally. The `@Throttle({ default: { ttl: 60000, limit: 5 } })` decorator on login/signup endpoints overrides with stricter limits.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /auth/signup | Untrusted registration input; password policy must be enforced server-side |
| client -> POST /auth/login | Untrusted credentials; brute-force risk |
| client -> POST /auth/refresh | Cookie-based; relies on httpOnly + SameSite for CSRF protection |
| client -> DELETE /auth/logout | Requires valid JWT; clears session state |
| client -> GET/PATCH /users/me | JWT-protected; user can only access own data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Spoofing | POST /auth/login | mitigate | Rate limiting via @nestjs/throttler: 5 requests per 60 seconds on login endpoint. ThrottlerGuard registered as APP_GUARD with per-endpoint overrides. |
| T-02-06 | Spoofing | POST /auth/signup | mitigate | Rate limiting: 5 requests per 60 seconds. Email uniqueness at DB level (unique constraint). Password hashed with bcrypt (work factor 10). |
| T-02-07 | Spoofing | POST /auth/refresh | mitigate | Refresh token rotation: old token blacklisted in Redis on each use. Single-use prevents theft reuse. httpOnly cookie prevents JS access. |
| T-02-08 | Tampering | refresh token cookie | mitigate | Cookie attributes: httpOnly=true, secure=true (production), sameSite=strict. Path scoped to /auth to limit exposure. |
| T-02-09 | Repudiation | auth actions | accept | Audit logging deferred to Phase 13 (AUDT-01). Acceptable for v1 auth phase. |
| T-02-10 | Information Disclosure | password in API response | mitigate | User password field excluded from ALL Prisma select clauses. Never returned in any API response. |
| T-02-11 | Information Disclosure | JWT secrets | mitigate | Separate JWT_ACCESS_SECRET and JWT_REFRESH_SECRET. Read from process.env via ConfigService. Never hardcoded. |
| T-02-12 | Denial of Service | POST /auth/signup | mitigate | ThrottlerGuard rate limiting. ValidationPipe rejects malformed input before business logic runs. |
| T-02-13 | Elevation of Privilege | role manipulation | mitigate | Role field not accepted in signup DTO (whitelist: true strips it). Default STUDENT set server-side. Role changes are admin-only (Phase 3). |
